The improvement loop

One change at a time, against
a baseline that doesn’t move.

“When a measure becomes a target, it ceases to be a good measure.”Goodhart’s law · Marilyn Strathern

Eval harness · validated, then a frozen baseline
One changeproposed by the agent
Captureoutputs, kept apart from grading
Verdictcross-vendor panel, frozen rubric
Keep or revertthe lesson becomes memory
Rules of evidence
i.
The model never grades its own work.

Your agent’s vendor never sits on the panel.

ii.
Agreement, or no score.

At least two vendor families must answer, or there is no score.

iii.
Memory that compounds.

Findings become cards, searched with 66 starter methods.

90%→0%

Get started

On your machine in about five minutes.

~/titration
$ git clone https://github.com/kaithoughtarchitect/titration.git
$ cd titration
$ docker compose up -d        # Postgres + pgvector
$ npm install
$ cp .env.example .env       # add OPENROUTER_API_KEY
$ npm run setup

# connect your agent, e.g. Claude Code
$ claude mcp add titration -- npx tsx "$PWD/server/server.ts"

New here? Start with examples/ticket-triage: two planted bugs, one measured fix.

You need

  • Node.js 22.11+ and Docker
  • An OpenRouter key. The claude · codex · grok CLIs can fill up to two judge seats.

Help build it

  • Add a learning to the starter pack
  • Verify the grok judge door
  • Run it on a real agent change, open an issue
